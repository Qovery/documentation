## Overview

The Qovery Slack integration sends real-time notifications to your Slack channels when deployments fail, enter failure loops, or recover. You can configure notification rules to filter by project, environment, and environment type, and customize the message template with variables.

Each notification includes actionable buttons to open the environment in the Qovery console, view deployment logs, mute notifications for 24 hours, or jump to notification settings.

Follow-up failures and recovery messages are grouped as thread replies to keep your channels clean.

## Setup

<Steps>
  <Step title="Connect your Slack workspace">
    1. Go to your Qovery console
    2. Navigate to **Organization Settings > Notifications > Slack**
    3. Click **Connect Slack**
    4. Authorize the Qovery bot for your Slack workspace

    <Info>
    You need admin access to the Slack workspace to authorize the app.
    </Info>
  </Step>

  <Step title="Create a notification rule">
    1. Click **Add notification rule**
    2. Choose which **Slack channel** receives the notifications
    3. Filter by **project**, **environment**, and **environment type** (production, staging, development, preview)
    4. Optionally customize the **failure message template** using variables
    5. Save the rule

    <Tip>
    Every public channel in your workspace is available. To use a private channel, invite the bot first by typing in the channel:
    ```
    /invite @Qovery Alerts
    ```
    </Tip>
  </Step>

  <Step title="Start receiving notifications">
    The next time a deployment fails or recovers in a matching environment, you will receive a notification in the configured Slack channel.
  </Step>
</Steps>

## Notification types

| Notification | Description | Format |
|-------|-------------|--------|
| **Deployment failure** | Sent when a deployment fails | New message in the channel |
| **Failure loop** | Sent when consecutive failures occur on the same environment | Thread reply on the original failure message |
| **Recovery** | Sent when a deployment succeeds after a failure | Thread reply with duration since first failure |

## Message template variables

When creating or editing a notification rule, you can customize the failure message using these variables:

| Variable | Description | Example |
|----------|-------------|---------|
| `{{organization_name}}` | Name of the organization | `Acme Corp` |
| `{{project_name}}` | Name of the project | `Backend API` |
| `{{environment_name}}` | Name of the environment | `production` |
| `{{environment_type}}` | Type of the environment | `PRODUCTION` |
| `{{failed_services}}` | List of failed services with their type | `api (APPLICATION), worker (CONTAINER)` |
| `{{failed_step}}` | Step where the deployment failed | `Deployment` |
| `{{triggered_by}}` | Who triggered the deployment | `John Doe` |
| `{{error_message}}` | Error message from the deployment (truncated to 500 chars) | `Pod crashloopbackoff...` |
| `{{console_url}}` | Direct link to the environment in the console | |
| `{{logs_url}}` | Direct link to the deployment logs | |
| `{{alert_settings_url}}` | Direct link to the notification settings page | |

### Default template

If you don't customize the message, the default template is:

```
Deployment failed on {{environment_name}} ({{environment_type}}) in {{project_name}}.
Failed services: {{failed_services}}. Triggered by {{triggered_by}}.
```

## Notification buttons

Each deployment failure notification includes four buttons:

- **Open in console** — Opens the environment overview in the Qovery console
- **View logs** — Opens the deployment logs for the failed environment
- **Mute 24h** — Silences all notifications for this environment on this channel for 24 hours
- **Notification settings** — Opens the Slack notification settings page

## Mute

Clicking **Mute 24h** on a notification silences all notifications for that environment on that channel for 24 hours. During this period, deployment failures and recovery events are still processed but no Slack messages are sent.

The mute is automatically lifted after 24 hours, or when a successful deployment occurs.

## Disconnect

To disconnect your Slack workspace:

1. Go to **Organization Settings > Notifications > Slack**
2. Click the trash icon next to the workspace name

<Warning>
Disconnecting a workspace automatically deletes all notification rules associated with it.
</Warning>

## Observability alerting via webhooks

If you use Qovery's observability alerting (CPU, memory, errors, latency), you can send those alerts to Slack using incoming webhooks. This is a separate flow from the Slack Bot deployment notifications above.

<Steps>
  <Step title="Create a Slack App with Incoming Webhooks">
    1. Navigate to the [Slack app creation page](https://api.slack.com/apps) and create a new app
    2. Activate **Incoming Webhooks** in the app settings
    3. Add a new webhook to your workspace and select the target channel
    4. Copy the generated webhook URL
  </Step>

  <Step title="Add a notification channel in Qovery">
    1. Navigate to the **Alerts** section in the Qovery Console
    2. Click on **Notification channel**
    3. Click **Add channel**
    4. Enter a **Display name** (e.g., "Production Alerts") and paste the **Webhook URL**
    5. Click **Confirm creation**
  </Step>

  <Step title="Create alert rules">
    Create alert rules with conditions (CPU, memory, etc.) and assign them to the notification channel you created. See the [Alert Conditions guide](/configuration/integrations/observability/qovery-observe#alert-conditions-guide) for details.
  </Step>
</Steps>

## Legacy deployment webhooks

If you were using webhook-based deployment notifications (not the Slack Bot above), they will continue to work. See the [Webhooks documentation](/configuration/integrations/webhooks) for details.
