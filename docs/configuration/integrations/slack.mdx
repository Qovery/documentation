## Overview


Each notification includes actionable buttons to open the environment in the Qovery console, view deployment logs, mute alerts for 24 hours, or jump to alert settings.

Follow-up failures and recovery messages are grouped as thread replies to keep your channels clean.

## Setup

<Steps>
  <Step title="Connect your Slack workspace">
    1. Go to your Qovery console
    2. Navigate to **Organization Settings > Notifications > Slack**
    3. Click **Connect Slack**
    4. Authorize the Qovery bot for your Slack workspace

    <Info>
    You need admin access to the Slack workspace to authorize the app.
    </Info>
  </Step>

  <Step title="Create an alert rule">
    1. Click **Add alert rule**
    2. Choose which **Slack channel** receives the alerts
    3. Filter by **project**, **environment**, and **environment type** (production, staging, development, preview)
    4. Optionally customize the **failure message template** using variables
    5. Save the rule

    <Tip>
    Every public channel in your workspace is available. To use a private channel, invite the bot first by typing in the channel:
    ```
    /invite @Qovery Alerts
    ```
    </Tip>
  </Step>

  <Step title="Start receiving alerts">
    The next time a deployment fails or recovers in a matching environment, you will receive a notification in the configured Slack channel.
  </Step>
</Steps>

## Alert types

| Alert | Description | Format |
|-------|-------------|--------|
| **Deployment failure** | Sent when a deployment fails | New message in the channel |
| **Failure loop** | Sent when consecutive failures occur on the same environment | Thread reply on the original failure message |
| **Recovery** | Sent when a deployment succeeds after a failure | Thread reply with duration since first failure |

## Message template variables

When creating or editing an alert rule, you can customize the failure message using these variables:

| Variable | Description | Example |
|----------|-------------|---------|
| `{{organization_name}}` | Name of the organization | `Acme Corp` |
| `{{project_name}}` | Name of the project | `Backend API` |
| `{{environment_name}}` | Name of the environment | `production` |
| `{{environment_type}}` | Type of the environment | `PRODUCTION` |
| `{{failed_services}}` | List of failed services with their type | `api (APPLICATION), worker (CONTAINER)` |
| `{{failed_step}}` | Step where the deployment failed | `Deployment` |
| `{{triggered_by}}` | Who triggered the deployment | `John Doe` |
| `{{error_message}}` | Error message from the deployment (truncated to 500 chars) | `Pod crashloopbackoff...` |
| `{{console_url}}` | Direct link to the environment in the console | |
| `{{logs_url}}` | Direct link to the deployment logs | |
| `{{alert_settings_url}}` | Direct link to the alert settings page | |

### Default template

If you don't customize the message, the default template is:

```
🚨 Deployment failed on {{environment_name}} ({{environment_type}}) in {{project_name}}.
Failed services: {{failed_services}}. Triggered by {{triggered_by}}.
```

## Notification buttons

Each deployment failure notification includes four buttons:

- **Open in console** — Opens the environment overview in the Qovery console
- **View logs** — Opens the deployment logs for the failed environment
- **Mute 24h** — Silences all alerts for this environment on this channel for 24 hours
- **Alert settings** — Opens the Slack notification settings page

## Mute

Clicking **Mute 24h** on a notification silences all alerts for that environment on that channel for 24 hours. During this period, deployment failures and recovery events are still processed but no Slack messages are sent.

The mute is automatically lifted after 24 hours, or when a successful deployment occurs.

## Disconnect

To disconnect your Slack workspace:

1. Go to **Organization Settings > Notifications > Slack**
2. Click the trash icon next to the workspace name

<Warning>
Disconnecting a workspace automatically deletes all alert rules associated with it.
</Warning>

## Legacy webhook integration

If you were using the previous webhook-based Slack integration, it will continue to work. The new Slack bot integration is an additional option that provides richer notifications with actionable buttons and thread grouping.

For the legacy webhook setup, see the [Webhooks documentation](/configuration/integrations/webhooks).
