An organization is a shared account where developers can collaborate across many projects. Organization owners and admins can manage all aspects of the organization, from clusters to member access.

## Prerequisites

To follow this section, you must have [created an account](https://console.qovery.com/signup).

## Creating an Organization

### When Signing Up

When you sign up for Qovery, you will be asked to create your first organization and project. You will need to:

1. Sign in through your Git provider (GitHub, GitLab, or Bitbucket), Google or Microsoft
2. Fill in your profile: full name, a work email (personal email domains are rejected), and company name. Submitting creates your organization and a first project automatically
3. Choose how to set up your first cluster: connect your own cloud account if you have cloud admin access, or set up a local demo cluster otherwise

You start on the Scale plan during your trial. For more information on available plans, visit the [pricing page](https://www.qovery.com/pricing).

Qovery also has a Free plan, with no time limit and no credit card: 3 users plus unlimited AI agents, 1 cluster of your own, and 1,000 deployment minutes a month with a hard stop: at the limit, new deployments pause until next month or until you upgrade, and Free never bills overage. It includes preview environments and environment cloning, with community support. See the [pricing page](https://www.qovery.com/pricing) for the current plans and limits.

If you have access to multiple organizations, you can switch between them:

1. Locate the organization dropdown in the header
2. Click on the dropdown to see all available organizations

## Delete an Organization

<Warning>
  Deleting an organization is **irreversible**. All data associated with the
  organization will be permanently deleted.
</Warning>

To delete an organization:

1. Navigate to Organization Settings
2. Scroll to the "Danger Zone" section
3. Click "Delete Organization"
4. Confirm the deletion by typing the organization name

## Billing

Manage your organization's billing and subscription:

- **View Invoices**: Access all past and current invoices
- **Payment Methods**: Add or update credit cards and payment details
- **Subscription**: Upgrade or downgrade your plan
- **Usage**: Monitor resource usage and costs

During the trial, add a credit card to activate your organization on one of the **Starter**, **Growth**, or **Scale** plans, billed monthly once the trial ends. You can switch between these plans until the trial ends.

<Info>
When you create an organization or add a payment card, you must provide your billing details, including a billing address. A **VAT number** is required for billing addresses in EU countries and optional elsewhere. Postal codes are validated against the expected format for the selected country.
</Info>

For pricing details, visit the [pricing page](https://www.qovery.com/pricing).

## Agent Experience

**Agent Experience** gathers in one place how your team's coding agents work with Qovery. Open it from the **Agent Experience** tab of your organization, next to **Audit Logs**. The organization overview also shows a card that leads there until you dismiss it.

The Overview opens with the idea behind it: agents can do real infrastructure work on their own when every operation is checked at the API. Agent Experience sets that up in three parts: **Guide** agents with the Copilot and skills, tailored per team and per person with skill presets; **Control** them with policy tokens, so each agent gets exactly the permissions its job needs, checked on every API call and denied by default; and **Observe** what they did and what was blocked, in agent activity and the audit logs.

Its side menu has seven pages, in this order:

- **Overview**: on the first visit, an introduction, "Qovery is agent first", and a single **Turn on AI** button (see [Turn on AI](#turn-on-ai)). Until your setup is complete, a checklist of five steps, with the next one highlighted: turn on AI, connect an agent, create a preset, create a policy token, and watch what agents do. Once agents are connected and the organization has a preset and a policy token, the page shows this week's numbers (agent actions, denied actions, members using agents, skill loads), the active presets, the policy tokens in use, the latest denied actions, and suggestions.
- **Automate**: agents that run on their own, on a schedule or on an event. Each one gets a policy token that allows exactly its job: anything else is refused at the API, and every call is logged. The jobs are the [agent policy examples](/configuration/organization/policy-examples/overview), safest first: Investigate, Hygiene, Cost, Reliability and Change. One-shot operations are not listed here. Each job says what the agent does, what it can never do, and a suggested trigger, such as a webhook when an incident fires or `0 8,20 * * 1-5` to stop idle environments in the evening and start them in the morning. Its **Run it on its own** sheet has two steps: create the policy token, prefilled with the example's name, description and policy (replace the `REPLACE_WITH_` IDs, and keep the token value, shown once), then schedule the agent, in one of two ways. The first is the coding agent you already use (Claude Code, Codex, Cursor, OpenCode, Gemini CLI, VS Code Copilot, or any agent with the Qovery skills), signed in with the token outside the prompt (in `QOVERY_CLI_ACCESS_TOKEN` or the MCP header) and started by the agent's own scheduling, a CI cron job or the event. The second, recommended, is an [Agent Task](/configuration/agent-tasks/overview) on Qovery, with the Qovery MCP server authenticated by that token: it runs next to your services on its own schedule or webhook, with no laptop or CI to keep running. The page lists the Agent Tasks templates under **Or run agents on Qovery**. **Copy prompt** and **Read the example** are on each job too. **Automate a new job** turns a recurring job you describe into a `/qovery-policy-token` command for your coding agent, then you schedule it the same way. See [Run it on its own](/configuration/organization/policy-examples/overview#run-it-on-its-own).
- **Copilot**: what the [Console AI Copilot](/copilot/console) does (answers questions about your services, deployments and clusters in the Console, troubleshoots a failed deployment from its logs and events, takes actions such as deploys and restarts only in read-write mode, and runs scheduled tasks), its status, and its settings: access source, access mode, scheduled tasks, and **Disable**. The old **Organization settings → AI settings → Copilot** page redirects here.
- **Connect your agent**: the commands to install the [Qovery agent skills](/getting-started/quickstart/agent-skills), the [Qovery CLI](/cli/overview) and the [Qovery MCP server](/copilot/mcp-server), and what your organization's preset gives agents.
- **Skill presets**: create, edit and assign [skill presets](/copilot/skill-presets) (Preview), see their history and usage, and which skills members' agents loaded.
- **Policy tokens**: the organization's [API Policy Tokens](/configuration/organization/api-policy-token) with their role, last use and expiry, and a button to create one. Each token shows a bar of its last 7 days, allowed and denied calls per day, and a **See activity** link that opens Activity filtered on that token. Deleted tokens that made calls in the last 30 days are listed below. Creating a token opens the form in **Organization settings**, where you also edit and delete tokens, in the **API token** section.
- **Activity**: one view of what members' agents did (through the skills and the MCP server) and what policy tokens did, allowed and denied. Filter by period, actor (everyone, all members, all policy tokens, or one member or token), skill, source and outcome. The filters are kept in the URL, so you can share a filtered view. Break it down by member, by token or by skill, and click a row to filter the whole page. **What was blocked** lists the refused calls, with **Show only denied**. See [Activity](/copilot/skill-presets#activity).

An agent counts as connected once the organization has at least one skill load, agent action or denied call in the last 30 days.

**Who sees what**

| Page | Owners and Admins | Other members |
|------|-------------------|---------------|
| Overview | The setup checklist, or the organization's numbers once set up | **Your agent setup**: what their agent receives and their own activity, read-only |
| Automate | Yes, with **Create policy token** | Read-only: **Copy prompt** and links, no token creation |
| Copilot | Status and settings | Status only |
| Connect your agent | Yes | Yes |
| Skill presets | Create, edit and assign | Read-only view of what their agent receives |
| Policy tokens | Yes, with each token's last 7 days | Not in the menu |
| Activity | The whole organization, members and policy tokens | **Your activity**: their own, with no actor filter and no token breakdown |

### Turn on AI

AI features are the organization's opt-in to AI. The Copilot needs them, and so does the security review that checks every skill preset before it is saved. Owners and Admins turn everything on in one step:

1. Open **Agent Experience**, then click **Turn on AI**.
2. Read the Copilot terms and confirm.

This one confirmation turns on the organization's AI features and the Copilot, in read-only mode. To allow actions such as deploys and restarts, change the access mode later on the **Copilot** page. If the Copilot cannot be turned on, AI features stay on and you can retry from the same page.

Other members cannot turn on AI. They see the Copilot status only.

### Agent

<AgentTasksEvolutionNote />

The **Agent** section manages what's shared with every [Agent Task](/configuration/agent-tasks/overview) in the organization: AI provider tokens under **Agent > Token**, and MCP servers under **Agent > MCP**.

**Token**: create and manage the AI provider tokens used by agent tasks. Qovery currently supports [Claude](https://www.anthropic.com/) (Anthropic), [AWS Bedrock](https://aws.amazon.com/bedrock/), and Anthropic-compatible gateways as providers. See [Choose a Provider and Model](/configuration/agent-tasks/overview#creating-an-agent) for the Anthropic-compatible Base URL and limits. A token created here, or created on the fly from an agent task's **Choose a Provider** step, is saved to this list and can be reused by any other agent task in the organization instead of re-entering credentials each time.

**MCP**: connect any remote HTTPS MCP server here (name, URL, and headers) to make it available when configuring an individual agent.

<Info>
Qovery's own MCP server is added here automatically, organization-scoped and read-only, as soon as any agent task adds a Qovery service as Context, see [Add MCP Servers](/configuration/agent-tasks/overview#creating-an-agent). To add it yourself instead, for example with write access, use `https://mcp.qovery.com/mcp` and authenticate with an [API Policy Token](/configuration/organization/api-policy-token) (a regular API token works too).
</Info>
