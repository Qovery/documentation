Connect a Kubernetes cluster you already run to Qovery by installing the Qovery Operator. Qovery then installs and updates the Qovery stack on the cluster.

<Note>
Another provider or an on-premise cluster? Follow the [installation with the Qovery CLI](/configuration/integrations/kubernetes/byok-legacy). For the local demo, see [Test & Learn Locally](/getting-started/quickstart/docker).
</Note>

<Info>
Want Qovery to provision and manage the cluster for you instead? See [Create Your Cluster](/getting-started/quickstart/cloud) for the managed path (AWS, GCP, Azure, Scaleway).
</Info>

## Prerequisites

<Check>A Qovery organization on the Enterprise plan</Check>
<Check>A running Kubernetes cluster on AWS (EKS), GCP (GKE) or Scaleway (Kapsule), with at least one node that can host a build, with 4 vCPU and 8 GiB of memory free, for example an 8 vCPU node. A 4 vCPU node is not enough.</Check>
<Check>`kubectl` access to the cluster with `cluster-admin` rights and `helm`, only to install the Operator once</Check>
<Check>A cloud credential for the provider of the cluster, with the [required permissions](/configuration/integrations/kubernetes/byok#credential-permissions)</Check>
<Check>Active Qovery account - [Sign up here](https://start.qovery.com)</Check>

<Warning>
The Qovery Operator installation is in Preview and is enabled organization by organization. Contact Qovery Support to enable it on yours. Check the [full prerequisites](/configuration/integrations/kubernetes/byok#prerequisites) before you start (default StorageClass when Loki uses a volume, EBS CSI driver on EKS, load balancer, no existing cert-manager, ExternalDNS or Envoy Gateway), because a missing one can make the deployment fail. See also the [current limitations](/configuration/integrations/kubernetes/byok#current-limitations).
</Warning>

## Installation

<Steps>
  <Step title="Create the cluster in the Console">
    Go to **Clusters**, add a cluster and, under **Connect existing cluster (BYOK)**, select **AWS**, **GCP** or **Scaleway**. Fill in the cluster name, the credential and the region. On **Configure Qovery Operator**, keep the defaults and click **Continue**. Qovery adds the cluster to your organization.
  </Step>

  <Step title="Install the Qovery Operator">
    Download the Helm values file and run the Helm command shown in the Console, with a kubeconfig pointing to your cluster. The values file contains the cluster credential, so keep it private and delete it once the Operator is installed. Keep the page open, and the Console opens the cluster profile once the Operator connects.
  </Step>

  <Step title="Deploy the platform profile">
    Review the profile settings. Click **Save and deploy** if you changed one, or **Deploy** in the **Manage deployment** menu of the cluster to keep the defaults. Qovery installs the Qovery stack on the cluster.
  </Step>
</Steps>

See [Bring Your Own Kubernetes (BYOK)](/configuration/integrations/kubernetes/byok) for each step in detail, and its [troubleshooting](/configuration/integrations/kubernetes/byok#troubleshooting) if the Operator does not connect or the deployment fails.
