## Overview

Manage environments and their lifecycle within your Qovery project.

## Commands

### List Environments

List all environments in current project:

```bash
qovery environment list
```

### Deploy Environment

Deploy all services in an environment:

```bash
qovery environment deploy --environment "env-name"
```

Deploy with specific services or versions:

```bash
qovery environment deploy \
  --environment "env-name" \
  --applications "app1:commit_id,app2:commit_id" \
  --watch
```

### Deployment Logs

Print the deployment logs of an environment: the engine output (build, deploy, health checks) shown in the **Deployment logs** tab of the console. These are the logs of the deployment itself, not the runtime output of a running service. For runtime logs, use [`qovery log`](/cli/commands/log).

```bash
qovery environment deployment logs --environment "env-name"
```

Without `--execution-id`, the logs of the latest deployment are printed (the API returns at most the last 1000 lines). To read a past deployment, pass its execution ID as listed by `qovery environment deployment list`:

```bash
qovery environment deployment logs \
  --environment "env-name" \
  --execution-id "$EXECUTION_ID"
```

Scope the output to a single service with `--service` (by name) or `--service-id` (by UUID); the two are mutually exclusive. Environment-level lines are kept for context:

```bash
qovery environment deployment logs --environment "env-name" --service "my-api"
```

<Note>
The console additionally scopes lines to the deployment stage a service belongs to, which the CLI does not resolve, so a few stage-level lines from other stages may appear in a service-scoped view.
</Note>

### Stop Environment

Stop all services in an environment:

```bash
qovery environment stop --environment "env-name"
```

### Cancel Environment Deployment

Cancel an ongoing environment deployment:

```bash
qovery environment cancel --environment "env-name"
```

### Delete Environment

Delete an environment:

```bash
qovery environment delete --environment "env-name"
```

### Update Environment

Update an environment's name or type:

```bash
qovery environment update \
  --environment "env-name" \
  --name "new-name"
```

### Clone Environment

Clone an existing environment:

```bash
qovery environment clone \
  --environment "production" \
  --new-environment-name "staging-clone"
```

## Examples

### Deploy Environment

```bash
# Set context
qovery context set

# Deploy all services and watch
qovery environment deploy \
  --environment "my-env" \
  --watch

# Deploy specific applications with specific commits
qovery environment deploy \
  --environment "my-env" \
  --applications "api:abc1234,frontend:def5678" \
  --watch
```

### Cancel a Deployment

```bash
# Cancel current deployment
qovery environment cancel --environment "my-env"

# Force cancel and watch
qovery environment cancel \
  --environment "my-env" \
  --force \
  --watch
```

### Clone Production to Staging

```bash
# Clone environment
qovery environment clone \
  --environment "production" \
  --new-environment-name "staging-test" \
  --environment-type STAGING

# Clone to a different project and cluster
qovery environment clone \
  --environment "production" \
  --new-environment-name "staging-test" \
  --target-project "other-project" \
  --cluster "staging-cluster"

# Deploy cloned environment
qovery environment deploy --environment "staging-test"
```

### Update Environment

```bash
# Rename an environment
qovery environment update \
  --environment "old-name" \
  --name "new-name"

# Change environment type
qovery environment update \
  --environment "my-env" \
  --type PRODUCTION
```

### `qovery environment deployment logs`

Print the deployment logs of an environment

```text Description from qovery environment deployment logs --help
Print the deployment logs of an environment -- the engine output shown in the "Deployment logs" tab of the console.

These are the logs of a deployment itself (build, deploy, health checks), not the runtime output of a
running service: for that, use "qovery log".

Without --execution-id, the logs of the latest deployment are printed. The API returns at most the
last 1000 lines.

--service matches the service name carried by each log line, so it works for every service type
(including Terraform services). Use --service-id to match on the service uuid instead; the two are mutually exclusive. Either way,
the environment-level lines are kept for context.

Note: the console additionally scopes lines to the deployment stage the service belongs to, which
the CLI cannot resolve without an extra lookup, so a few stage-level lines from other stages may
appear in a service-scoped view.
```

| `--errors-only` |  | bool |  |  | Only print the log lines carrying an error |
| `--execution-id` |  | string |  |  | Execution Id of a past deployment, as listed by 'qovery environment deployment list' (default: latest deployment). Also accepted as --id, matching 'deployment explain' |
| `--json` |  | bool |  |  | Print the logs as JSON |
