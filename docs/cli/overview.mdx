## Overview

The Qovery CLI (Command Line Interface) enables you to interact with Qovery directly from your terminal. Deploy applications, manage environments, stream logs, and more - all without leaving your command line.

## Installation

<InstallQoveryCLI />

### Verify Installation

```bash
qovery version
```

## Authentication

Before using the CLI, you need to authenticate:

```bash
qovery auth
```

This will open a browser window for authentication. Once completed, you'll be ready to use the CLI.

### API Token Authentication

You can also authenticate using an API token:

```bash
export QOVERY_CLI_ACCESS_TOKEN="your-api-token"
qovery auth
```

Generate an API token from the [Qovery Console](https://console.qovery.com/platform/organization/api-tokens).

## Configuration

The CLI stores configuration in `~/.qovery/context.json`. You can manage multiple contexts for different organizations or clusters.

### Set Default Context

```bash
qovery context set
```

### List Contexts

```bash
qovery context list
```

## Watching Operations

Most deployment commands accept the `--watch` (`-w`) flag to wait until the targeted services finish and report their final status. The command exits with a non-zero status if a watched service fails, is canceled, ends in an unexpected state, or no longer exists — useful in CI/CD pipelines.

By default, a watch stops after **1 hour** and exits with an error if the services have not finished. To wait longer (for example for long builds or Terraform runs), set the `QOVERY_CLI_WATCH_TIMEOUT` environment variable to a [Go duration](https://pkg.go.dev/time#ParseDuration) such as `2h`:

```bash
export QOVERY_CLI_WATCH_TIMEOUT="2h"
qovery environment deploy --watch
```

## Blueprint Databases

Databases created from a database blueprint are Terraform services, and the CLI supports them like native databases.

### List Blueprint Databases

`qovery database list` lists the blueprint databases of the current environment together with the native databases. Blueprint databases appear with the type `Blueprint database`, and the output shows their status, host, and port:

```bash
qovery database list
```

Add `--show-credentials` to display the login and password, as for native databases. If the credentials are not available (the database is not deployed yet, or you are not allowed to read them), only the host and port are shown.

With `--json`, blueprint databases are included in the output with the same fields as native databases. The `login` and `password` fields are only filled when `--show-credentials` is set.

### Port-Forward to a Blueprint Database

`qovery port-forward` accepts the Console URL of a Terraform service, such as a blueprint database. Pass the URL of the service followed by the ports to forward, in the `local_port:remote_port` format:

```bash
qovery port-forward "<service-console-url>" --port 5432:5432
```

If the service ID in the URL does not exist in the environment, the command fails with a `not found in environment` error.

## Blueprints

### Point a Blueprint at a Newer Major Version

`qovery blueprint upgrade-major` points a blueprint service at the latest tag of a newer major version, for example PostgreSQL 14 to 18. It works for any blueprint service, Terraform or Helm. Run it without `--major` to list the newer majors and what moving to each one would do:

```bash
qovery blueprint upgrade-major -n <service name>
```

Then pick a major:

```bash
qovery blueprint upgrade-major -n <service name> --major 18
```

The command shows what will happen and asks for confirmation (`--yes` skips it), then updates the blueprint and deploys it. Add `--watch` to follow the deployment.

- **Relabel:** the service already runs that major, for example a database upgraded with an AWS Blue/Green deployment. Only Qovery's records change; the service is not touched.
- **Upgrade:** the service runs an older major. The next deployment upgrades it in place, which causes downtime for a database.
- **Not supported:** the move is refused and the command explains why, for example a lower major than the one running.

See [Moving to a newer major version](/configuration/blueprints#moving-to-a-newer-major-version) for details.
