## Overview

Use `qovery terraform` to run and manage the Terraform services of an environment from the terminal: list them, run a plan, plan and apply, delete their resources, unlock or migrate their state, and manage their external secrets.

## Examples

List the Terraform services of an environment:

```bash
qovery terraform list \
  --organization "Acme Corp" \
  --project "Backend Services" \
  --environment "production"
```

Run a plan without applying it, and follow it until it finishes:

```bash
qovery terraform plan --terraform "network" --watch
```

Plan and apply the newest commit of the branch:

```bash
qovery terraform plan-and-apply \
  --terraform "network" \
  --commit-id latest \
  --watch
```

Plan and apply several Terraform services at once:

```bash
qovery terraform plan-and-apply --terraforms "network,database"
```

### Access the Terraform state

`setup-backend` generates a `backend.tf` file that points Terraform at the state Qovery stores for a Terraform service. The command asks before it writes the file in the current directory. The state can contain secret values, so keep `backend.tf` and any local copy of the state out of version control.

`--terraform` (`-t`) takes the **ID** (UUID) of the Terraform service, not its name. Without it, the command uses the service in the current [context](/cli/commands/context).

```bash
qovery terraform setup-backend --terraform "$TERRAFORM_SERVICE_ID"
```

### `qovery terraform delete`

Delete terraform resources

```text Description from qovery terraform delete --help
Delete terraform resources and remove from Qovery.

By default, this will execute 'terraform destroy' to delete all resources
managed by this terraform service, then remove the service from Qovery.

Use --skip-destroy to keep the infrastructure resources but remove the
Qovery configuration. This is useful when you want to manage the resources
outside of Qovery or import them into another system.

Use --resources-only to delete the infrastructure resources but keep the
Qovery configuration. This is useful when you want to clean up resources
while keeping the terraform service definition in Qovery.
```
