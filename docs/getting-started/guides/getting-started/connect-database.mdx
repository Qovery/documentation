## Overview

This guide shows you how to create a database in your environment and connect it to your application.

<Tip>
For production, deploy a cloud provider managed database (for example Amazon RDS for PostgreSQL or MySQL, or Amazon ElastiCache for Redis) with a [Blueprint](/configuration/blueprints). See [Creating a Blueprint Service](/configuration/blueprints#creating-a-blueprint-service).
</Tip>

## Creating a Database

<Steps>
  <Step title="Navigate to Your Environment">
    In the Qovery Console, go to your project and select the [environment](/configuration/environment) where you want to add the database.
  </Step>

  <Step title="Add a Database via New Service">
    Click the **New Service** button, then either:
    - Select **Database** from the service type list, or
    - Search directly for the database you want (e.g., "MySQL", "PostgreSQL")
  </Step>

  <Step title="Configure Basic Settings">
    Configure your database:

    - **Database Type**: PostgreSQL, MySQL, MongoDB, or Redis
    - **Name**: Give your database a name
    - **Version**: Choose the database version
  </Step>

  <Step title="Configure Resources">
    Set the resource allocation for your database:

    - **vCPU**: CPU assigned to the database container
    - **Memory**: RAM assigned to the database container
    - **Storage**: Size of the persistent storage attached to the database
  </Step>

  <Step title="Create and Deploy">
    Review your settings and click **Create**. You can choose to create the database alone or create and deploy it immediately.
  </Step>
</Steps>

## Connecting Your Application

Qovery automatically injects database credentials as [environment variables](/configuration/environment-variables) when your application runs. You'll have access to a connection URI and individual connection details.

### Using the Connection URI

The easiest way to connect is using the connection URI environment variable:

```javascript
// Node.js with PostgreSQL example
const { Pool } = require('pg');

const pool = new Pool({
  connectionString: process.env.QOVERY_POSTGRESQL_Z9XXXXXX_DATABASE_URL,
});
```

### Available Environment Variables

For each database, Qovery provides:

- `QOVERY_POSTGRESQL_<DBID>_DATABASE_URL` - Complete connection string
- `QOVERY_POSTGRESQL_<DBID>_HOST` - Database host
- `QOVERY_POSTGRESQL_<DBID>_PORT` - Database port
- `QOVERY_POSTGRESQL_<DBID>_LOGIN` - Database username
- `QOVERY_POSTGRESQL_<DBID>_PASSWORD` - Auto-generated password
- `QOVERY_POSTGRESQL_<DBID>_DEFAULT_DATABASE_NAME` - Default database name

Replace `POSTGRESQL` with your actual database type (`MYSQL`, `MONGODB`, `REDIS`, etc.) and `<DBID>` with the database ID shown in the Console (visible in the **Variables** tab of your service).

<Note>
The exact variable names are always visible in the **Variables** tab of any service that has the database attached. You can copy them directly from there.
</Note>

## Database Management

### Backups

Databases created this way run as containers and have no automated backups or snapshots. For production, provision a cloud provider managed database with a [Blueprint](/configuration/blueprints) and configure and verify the provider's backup and retention settings.

## Best Practices

<Tip>
Start with small CPU and memory values and scale up as needed. For production workloads, use a [Blueprint](/configuration/blueprints) to provision a managed database.
</Tip>

<Warning>
Database passwords are generated automatically. Store them securely and rotate regularly.
</Warning>
