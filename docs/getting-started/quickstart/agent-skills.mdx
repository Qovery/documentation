## Skill reference

The install command installs all eleven skills. Your agent picks the skill from your prompt, or you can call it with its slash command (for example `/qovery-signup`).

| Skill | What it does | Example prompt |
|-------|--------------|----------------|
| `qovery` | Entry point. Routes your request to the right skill and handles quick operations: list, status, stop, restart, logs, clone, scale, custom domains, deployment history. | "List my Qovery environments" |
| `qovery-signup` | Creates a Qovery account from your terminal: installs the Qovery CLI if needed, authenticates with `qovery auth --headless` (the first login creates the account), creates your first organization, then hands off to qovery-onboard. Never handles raw tokens. | "Create a Qovery account and log me in" |
| `qovery-onboard` | Guided setup. Understands your role, experience, and constraints, then recommends and sets up the Qovery configuration: cloud provider, cluster, environments, RBAC, security, and cost defaults. Handles BYOK and platform migrations. | "I'm new to Qovery, help me get started" |
| `qovery-deploy` | From source code to a running app: analyzes the codebase, creates a Dockerfile if missing, provisions databases, and deploys with the CLI and API or with Terraform. | "Deploy my application with Qovery" |
| `qovery-troubleshoot` | Diagnoses and fixes deployment failures, crashes, connectivity and performance issues: 8-layer diagnosis, 20+ error patterns, MCP Server integration, and runbook generation. | "My deployment is failing" |
| `qovery-optimize` | Optimizes costs and right-sizes resources from historical consumption, estimates cloud costs, and generates reports with CSV export. | "Optimize my Qovery costs" |
| `qovery-speedup` | Measures the deployment pipeline timeline, finds bottlenecks (build, startup, health check, scheduling), and proposes Dockerfile and configuration fixes. | "My deployments are slow" |
| `qovery-preview` | Creates a preview environment per pull request: detects or creates a blueprint environment, clones it for each PR, switches the branch, configures auto-shutdown (stop, delete, or recycle), and cleans up. | "Set up preview environments for my project" |
| `qovery-terraform` | Generates Terraform manifests (qovery/qovery provider) from an existing Qovery setup, imports resources into state, and validates them in a test clone. Never applies to the original without confirmation. | "Convert my environment to Terraform" |
| `qovery-policy-token` | Creates a scoped, least-privilege API Policy Token: turns your intent into an OPA/Rego policy, tests it locally and against the API, creates the token, and verifies it allows exactly what you want and denies everything else. | "I need a scoped token for an AI agent limited to the staging environment" |
| `qovery-assess` | Read-only assessment of a whole organization: inventories clusters, environments and services, runs 147 best-practice checks across reliability, security, performance, delivery, cost and disaster recovery, and writes a shareable gap analysis. Modifies nothing. | "Is my setup production-ready?" |

Source: [github.com/Qovery/qovery-skills](https://github.com/Qovery/qovery-skills).
